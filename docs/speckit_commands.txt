  1. /speckit-git-feature   — create branch
  2. /speckit-specify       — write spec from P-NN body + cited stakpak_arch.md

  6. /speckit-implement     — execute task by task with tests
  7. /speckit-analyze       — cross-artifact consistency (spec ↔ plan ↔ code)
  8. /speckit-checklist     — per-feature acceptance checklist
  9. /speckit-git-validate  — confirm branch + commits match Article VII

================================================================================
  EXECUTION PRINCIPLES
================================================================================

  1. NEVER skip /speckit-clarify. It's where v5's ambiguities surface.
     Resolving them before code is 10× cheaper than resolving them after.

  2. NEVER skip /speckit-analyze. Drift between spec/plan/tasks/code is silent
     and compounding. The check is non-destructive and fast.

  3. ONE P-NN per branch. Don't bundle. Article VII (PRs ≤500 lines preferred).

  4. EVERY PR description must include three sections:
     ## Constitution           — articles touched (e.g., I, III, XIII rule 5)
     ## stakpak_arch.md         — sections referenced (e.g., section 8, 27)
     ## Eval impact             — token cost delta vs baseline

  5. Constitution articles 1-12 govern decisions; Article XIII enumerates
     concrete anti-patterns. Article XIII rule N is always cited alongside
     the parent article (e.g., "Article V + Article XIII rule 5").

  6. The Validator (libs/engine/validator) MUST be on the path between
     Mapper and Generator. Bypassing it is a CI failure (Article III).

  7. Failures are loud. No silent fallbacks. No swallowed errors. No unwrap()
     in production code (Article IV + Article XIII rule 3).

  8. Adding a new agent requires explicit RFC + stage-gate approval (Article I).
     Stage 1 has zero agents. Stage 2 introduces Recovery + Cost Optimizer.
