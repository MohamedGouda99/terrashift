## Changes made

### UX-1 — `schema update --version` help text leaked dev jargon

**Before:**
> `Concrete version to capture (e.g. "5.30.0"). Required when --provider is set. Constraint expansion (~> 5.30) lands in S5 once the registry metadata-listing path is wired (see RFC §3 list_versions_matching).`

**After:**
> `Concrete version to capture (e.g. "5.30.0"). Required when --provider is set. Constraint syntax like "~> 5.30" is not yet supported — pass an exact version for now.`

**Why:** "S5", "RFC §3", "list_versions_matching" mean nothing to a Terrashift
user. They're internal stage and code references. The user needs to know:
(a) what to pass, (b) that constraint syntax doesn't work yet. Both are
now communicated without leaking the sausage-making.

**File:** `cli/src/commands/schema/update.rs`

---

### UX-2 — `schema show` cache miss leaked OS error 3

**Before:**
```
error: load aws@5.30.0 from C:\Users\.../tmp.X
  caused by: manifest/cache I/O: read C:\Users\.../tmp.X\aws\5.30.0\schema.json: The system cannot find the path specified. (os error 3)
```

**After:**
```
error: aws@5.30.0 is not cached.

  to capture it now:    terrashift schema update --provider aws --version 5.30.0
  to see what is cached: terrashift schema list
```

**Why:** "OS error 3" / "The system cannot find the path specified" tells
the operator nothing they can act on. The replacement names what's wrong
(version not cached) and gives the exact command to fix it AND the
exploratory command if they don't yet know what they want.

**File:** `cli/src/commands/schema/show.rs`

---

### UX-3 — `schema gc --keep-versions` help used Rust-specific term

**Before:**
> `Setting 0 deletes everything; setting `usize::MAX` is effectively a no-op gc.`

**After:**
> `Setting 0 deletes every cached version; very large values effectively disable gc.`

**Why:** `usize::MAX` is a Rust-specific compile-time constant. Most
operators will never have heard of it. "Very large values" communicates
the same thing without requiring Rust mental model.

**File:** `cli/src/commands/schema/gc.rs`

---

### UX-4 — `schema update` 44-second silent capture window

**Before:** the operator runs `terrashift schema update --provider aws --version 5.30.0`
and stares at a blinking cursor for ~30-45 seconds (the time `terraform init`
takes to download the AWS provider binary on a cold cache). Output:

```
Capturing 1 provider schema(s)...
[44 seconds of nothing]
  ✓ hashicorp/aws@5.30.0  (1300 resources, 44374 ms)
```

**After:** the line prints BEFORE the long-running call, with explicit
explanation of the wait, and is updated in place when the call finishes:

```
Capturing 1 provider schema(s)...
  ⏳ hashicorp/aws@5.30.0 (this runs `terraform init` — ~30s on a cold cache)... ✓ 1300 resources (37.0s)
```

**Implementation:** `print!` + `stdout().flush()` so the partial line shows
up *before* the blocking `fetcher.fetch().await` call. The success line
completes the same row with the resource count and wall-clock time.

**Why:** A blank screen is indistinguishable from a hung process. Users
reach for `Ctrl-C` after 30 seconds of silence even when the underlying
work is making progress. The `~30s on a cold cache` hint also sets the
right expectation — first run is slow, subsequent runs should be ~1-3s
because `TF_PLUGIN_CACHE_DIR` reuses the downloaded binary.

**File:** `cli/src/commands/schema/update.rs`

## What I deliberately did NOT change

- **Pipe-friendly silent mode for `schema list`** when piped to a non-TTY.
  `terrashift schema list | wc -l` returning `0` against an empty cache is
  the *correct* shell composition. The "Cache empty" hint only fires for
  TTY use because that's where the human is.

- **Tab-separated raw bytes in piped `schema list`**: a piped consumer
  almost always wants raw bytes for `awk` arithmetic, not "5.0 MB". TTY
  mode renders `5.0 MB` for human reading. Different consumers, different
  shapes — by design.

- **`terrashift version` does not include git SHA / build date.** Useful
  for bug reports but not blocking the MVP. Tracked as a follow-up.

- **Mixed forward/back slashes in Windows paths** (e.g.
  `C:/Users/.../tmp.X\manifest.json`). Cosmetic. Comes from `PathBuf::join`
  preserving the parent's slash style; would need normalisation in
  `format!` calls. Tracked as a follow-up.

## What I have NOT walked

- **TUI `/schemas` slash command and the cache-count footer field.**
  The TUI requires an interactive terminal; I can't easily exercise it
  through subprocess capture. Per OQ-2 the slash command is a Hint shim
  pointing at the CLI, so this is low risk — but it should be eyeballed
  in a real terminal session before declaring the MVP UX-complete.

- **`terrashift migrate` failure mode against missing schemas.** This
  requires Mapper integration with the runtime cache, which is S4 work.
  When that lands, the prompt section 8 touchpoint #6 ("a migrate that
  fails because a schema is missing") becomes testable.

- **Real `auto_update = "weekly"` cadence.** The background check fires
  on `migrate` startup; without a Mapper-driven `migrate` flow that's
  end-to-end exercisable, the cadence path is implementation-only today.

These three are S4/S5 work and not in scope for this RFC's MVP.
